# Progress tracker

A static page that shows what the project implements: overall percentage, status counters, one card and one expandable list per section, search with filters, and the last 50 status changes. Statuses live in `tracker/status.toml` and change by commit. Limit: 1,000 words.

## Files (`tracker/`)
| File | What it is |
|---|---|
| `rows.json` | Generated by `cargo xtask tracker gen` from the local game data: `{id, section, group, name}`, names only (no stats, values or art; [decisions.md](../decisions.md#public-release)). Committed. |
| `sections.toml` | Section order, titles, descriptions and which generator fills each. The project sections (`proj:` ids) and the league mechanics and trials (`mechanic:` ids) list their rows here. |
| `status.toml` | `[status]`: `"<id>" = { status, note, link }`, hand and agent edited. `[auto]`: written by `gen`, wins over `[status]`. A row that is in neither is **unknown**. |
| `site/` | Svelte 5 + Vite app. `tokens.css` is copied from `modules/web-admin/src` at build time (git-ignored). |

Statuses: `unknown`, `not_implemented`, `partial`, `implemented`, `fully_functional`, `not_planned`. No hour estimates: every row weighs the same. Progress counts a row as 0 (unknown, not implemented), 0.5 (partial), 0.85 (implemented) or 1 (fully functional); not-planned rows are left out of the total (`site/src/lib/progress.ts`).

## Row ids
`class:<Characters id>`, `asc:<Ascendancy id>`, `gem:<base item id>` (supports too; the id without `Metadata/Items/`), `passive:<PassiveSkills id>` (keystones, notables) and `passive:stat:<stat id>` (small passives, one row per first stat), `unique:<slug of the name>`, `base:<BaseItemTypes id>`, `currency:<id>`, `stat:<Stats id>` (stats used by mods and passives), `monster:<MonsterVarieties id>`, `area:<WorldAreas id>`, `mechanic:<name>`, `cmd:<command>` and `proj:<slug>`. Rows whose name starts with `[DNT` (developer placeholders) are left out.

## Commands
| Command | What it does |
|---|---|
| `cargo xtask tracker gen` | Needs `GameFiles/`. Rewrites `rows.json` and `[auto]` (every `cmd:` row parsed from the instance server's command table `COMMANDS` is `implemented`), then runs `check`. Run it after a game build or a command change. |
| `cargo xtask tracker check` | No game data: every id in `status.toml` is a row, every status is known, no id is in both tables. Runs in CI. |
| `cargo xtask tracker build` | Checks, then builds the site into `runtime/tracker-site/` (one `index.html` with script and styles inline, plus `data.js`), so it opens from a `file://` URL. `data.js` holds the rows with their statuses and the recent changes read from `git log -p tracker/status.toml`. `--data-only` rewrites only `data.js`. |
| `cargo xtask tracker edit [--port 8787]` | Builds, then serves the site on `127.0.0.1` with the pills as dropdowns plus note and link fields; each change writes `status.toml` (sorted, one line per row). Only a `Host` of `127.0.0.1` or `localhost` and JSON bodies are accepted; automatic rows cannot be edited. Nothing is committed. |

Site checks (in `tracker/site/`): `npm run check`, `npm test`.

## The page
Filters: free text, `is:<status>` (prefixes work: `is:fully`), `-is:<status>`, `in:<section>`; the query is kept in the URL hash (`#q=...`). A section opens when it has matches; the counters and the section cards set filters. Rows show their note on hover and a `docs` link (resolved against the repository's GitHub URL from `git remote get-url origin`).

## Hosting
`.github/workflows/tracker.yml` builds the site and deploys it to GitHub Pages on a push to `main` that touches `tracker/**`. `Settings, Pages, Source: GitHub Actions` must be set once.

## Agent rule
A commit that implements or changes something with a tracker row updates `tracker/status.toml` in the same commit, like the docs. Add rows for new project features to `sections.toml` (`proj:` ids). `cargo xtask tracker check` catches ids that no longer exist.
